# WASM execution extraction notes

**Status:** in progress. `mm_execution_state` owns target/storage, memory/cache, per-core CPU/SCS/NVIC/IT, clock and core-system state. The CLI delegates target MMIO and flash/SPI map binding to session operations. `include/m33mu/web.h` / `src/web_bridge.c` provide an initial public H563 API; `web/worker/` provides a v1 ES-module worker handler and build script. Its Node harness runs the worker entry against the generated Emscripten module and checks bounded load/step/run/pause/reset behavior plus yielding slices. The public API and worker queue timestamped GPIO inputs and stream output transitions. The public web step dispatches pending exceptions, shares exception entry/unstack, applies sleeping-core wake horizons and polls target devices at the 64-cycle quantum; H563 PendSV round-trip and WFI tests cover the API. The 32 MiB firmware cap is enforced by both the C session API and worker request validation. Current full serial CTest passes 106 enabled tests (one disabled), including native, Node/WASM and worker API tests. Exact CLI scheduler parity, UART, autonomous sleep resume, analog solver worker scheduling and broader peripheral timing remain incomplete.

## Current paths

- `cmake/wasm` builds a static core library, excluding `main.c`, GDB sockets, POSIX UART/PTY HAL, Linux Ethernet/USB host modules, optional TPM/capstone sources and TUI. Host-only transport references resolve to explicit unavailable stubs in `cmake/wasm/wasm_host_stubs.c`; host-independent target callback dispatch is in `src/target_runtime.c`. `scripts/test-web-execution-state.sh` links both `execution_state_test` and `web_session_test` against the archive and runs them in Node/WASM. The latter exercises the public C bridge, but does not provide browser worker messaging or the complete CLI scheduler.
- `cmake/wasm` builds a static core library, excluding `main.c`, GDB sockets, POSIX UART/PTY HAL, Linux Ethernet/USB host modules, optional TPM/capstone sources and TUI. Host-only transport references resolve to explicit unavailable stubs in `cmake/wasm/wasm_host_stubs.c`; host-independent target callback dispatch is in `src/target_runtime.c`. `scripts/test-web-execution-state.sh` links both `execution_state_test` and `web_session_test` against the archive and runs them in Node/WASM. `scripts/build-web-worker.sh` emits an ES-module WASM API plus worker entry, and `scripts/test-web-worker.sh` exercises the actual worker entry under Node against that module. This is initial RPC coverage, not complete production scheduling.
- `target_runtime_test` checks dispatch of the extracted target callbacks; its single static current-target pointer also makes the one-live-session constraint explicit. `mm_execution_state` is the production session owner used by `main.c`. Process-wide peripheral and signal state and exact whole-scheduler control remain outside it.
- `mm_execution_advance_cycles()` now centralizes the production virtual cycle counters, SysTick, target timer and signal clock updates. The CLI's main instruction path, translation-block execution, flash stalls and sleep paths, plus the secondary stepping helper, call this shared routine. Signal-trigger checks stay at the same instruction boundaries. `execution_clock_test` covers counter deltas, zero-cycle behavior, optional counter pointers and target timer advancement.
- The production scheduler counters now have an explicit `mm_execution_clock` owner: total cycles, virtual cycles, realtime sync baseline and poll batch count. The CLI resets this state at each run/reset boundary and both the production loop and secondary-core step helper advance it through `mm_execution_clock_advance()`. The older pointer-based primitive remains for independent callers/tests. CPU, map and code cache are session-owned too; peripheral instances, signal state and broader scheduling policy remain outside the owner.
- `mm_cpu_reset()` in the shared CPU core now clears the complete architectural CPU object and establishes secure thread mode, VTOR banks, and requested sleep state. The production startup/reset path uses the same function for the primary core and parked secondary core, then applies target boot register seeds and reads the reset vector. This makes the reset semantics directly reusable by session creation and prevents stale or uninitialized FP/DSP, stack-tracking, exception-stack, TrustZone-stack and exclusive-monitor state. Native tests check base and parked-core reset; the generated H563 CLI ELF boot remains green.
- `mm_execution_state` owns both cores' CPU, SCS, NVIC and IT-block state, the SCS multiplexer, active-core selector, scheduler clock, production map/MMIO storage/code cache, protection contexts, core-system context, selected target, flash/RAM storage and loader targets. `main.c` uses these members directly. State operations cover lifecycle, staged target setup, ELF loading, reset-vector application plus VTOR synchronization, primary-core cycle advancement, fetch/decode, fetch-fault callback dispatch, IT decisions/advancement and skip/execute, decoded execution, sleep wake and pending interrupt dispatch. Shared exception entry and unstack live in `execution_exception.c` and are used by the CLI and web bridge. Peripheral instances, process signal facilities, exact full instruction scheduling and complete session ownership remain open.
- `execution_irq.c` owns exception-priority and mask decisions. `mm_execution_irq_dispatch_pending()` applies PendSV/SysTick/IRQ candidate selection and delivery bookkeeping. `mm_execution_state_dispatch_pending()` binds that dispatch to owned per-core state and is used by the CLI and web bridge; its blocked-candidate policies preserve each caller's behavior. Exception entry/unstack are shared operations with CLI and web fault/diagnostic adapters. Tests cover both policies, bank selection, priority lookup, BASEPRI, external IRQ bookkeeping and an H563 PendSV round trip.
- `exc_return.c` owns Armv8-M EXC_RETURN encoding and decoding. The extended encoder preserves distinct stack and exception security state, PSP/thread mode, frame type and default callee stacking; the legacy three-argument API is a compatibility wrapper. `scs.c` owns banked SHCSR exception-active set/clear and ICSR VECTACTIVE updates. `execution_exception.c` owns architectural entry/stacking and EXC_RETURN unstack behind fault and diagnostic callbacks. Tail chaining remains disabled as in the prior CLI behavior. Tests cover encoder/decoder fields, banked SCS updates and exception frame behavior.
- `mm_target_storage` in `target_storage.c` owns target flash and RAM backing allocations. It computes RAM storage from non-aliased RAM regions, provides a safe destroy operation, and leaves the object empty on failed initialization. It is embedded in `mm_execution_state` and used by CLI/session setup; peripheral instances, signal state and parts of reset policy are still in `main.c` or process-global modules.
- `mm_elf_load_memory_bounded()` accepts a byte buffer and caller-selected maximum size, rejects oversized inputs before segment writes, validates ELF32 little-endian ARM program-header and segment bounds, maps PT_LOAD data into caller-owned flash/RAM/serial-flash buffers, and reports loaded address range. The compatibility `mm_elf_load_memory()` retains the prior no-policy-limit behavior and CLI path loading delegates to it. `image_loader_test` covers the cap rejection and accepted boundary; `scripts/test-web-elf-loader.sh` links the loader test as WASM and runs it in Node; CTest registers this smoke when `emcc` and Node are found. The browser session applies its documented 32 MiB default and permits callers to configure another cap through `mm_web_config`.
- `scripts/test_cli_elf_loader.py` generates a minimal H563 ELF with a reset vector and BKPT, then verifies normal CLI loading, reset, and instruction execution. This confirms the path wrapper and in-memory parser work together.
- Loader status: the browser/session product cap is 32 MiB by default, can be overridden through `mm_web_config`, and is enforced by the C ELF load and worker `loadFirmware` request before allocation. The public session test verifies a configured 96-byte cap rejects a 97-byte input and accepts a valid 96-byte H563 ELF; the worker validates the 32 MiB ceiling and its API harness covers firmware loading. `wasm_worker_api_test` now runs the same byte-identical generated H563 ELF through the CLI and public worker: after one MOV, the CLI trace and worker snapshot agree on PC, r0 and secure MSP. The CLI is forced off translation blocks for instruction-boundary comparison. Full CLI/session memory-map parity and comparing broader instruction streams remain open.
- `src/main.c::step_core_simple()` handles a limited subset of timing/exception logic for a secondary path. `src/runloop.c::mm_step()` executes only NOP and branch placeholders. Neither is the production H563 path.
- The primary production path uses session operations for reset-vector application, fetch/decode, fetch-fault callback dispatch, IT decisions/advancement, IT predicate skip versus execute, and decoded execution. `mm_execution_state_step_decoded()` completes one decoded instruction per call and preserves the rule that an IT instruction executes regardless of the current predicate. The native session test loads ELF bytes into H563 memory, fetches its first MOV, steps it once, and verifies the register and PC. A worker can enforce an instruction budget by making a bounded number of these calls, with fetch/decode and host policy between calls. The CLI supplies policy callbacks and output state. The session also applies WFI/WFE wake rules, computes the earliest SysTick/signal/host wake horizon with the production one-cycle signal floor (tested for deadline minima and invalid cores), dispatches pending exceptions and provides shared entry/unstack. `main.c` delegates its sleeping-core deadline selection to that operation while supplying only the optional GDB deadline. The web bridge now uses the sleep horizon and target poll quantum; exact callback ordering, cycle fidelity, trace/CLI policy and complete scheduler parity remain open.
- Target USART/SPI/Ethernet callback polling and cycle-quantum bookkeeping now run through session operations used by the production loop. Native tests verify due-threshold handling, callback ordering and quantum reset. USB polling and TUI work remain CLI host services; target device instances and signal facilities are still process-global.
- The same `execution_state_test` executable passes natively and as Node/WASM. The WASM smoke uses a 1 MiB test stack for local session fixtures. It validates shared session primitives and H563 pending-PendSV entry/unstack. `web_session_test` also runs under Node/WASM and exercises an ELF that pends PendSV, returns through BX LR and reaches BKPT using the public API. Browser messaging is covered by the worker harness; full target peripheral startup remains incomplete.
- The public bridge currently accepts only `stm32h563`; ELF input is capped at 32 MiB by default (or a caller-provided cap). It runs bounded instruction batches and stops on BKPT. GPIO inputs can be timestamped in virtual nanoseconds (unsigned decimal string in the worker), queue up to 64 events, and apply at the first instruction boundary at or after their timestamp, with FIFO order for equal cycles. A past timestamp and a full input queue are rejected. The worker cannot accept new messages during a synchronous slice, so schedule future input before starting `step`/`run`. Output pad transitions are buffered to 4096 events and streamed after each slice; overflow is surfaced as a fault. Exception entry, pending dispatch and unstack are implemented; complete fault recovery and scheduler-equivalent peripheral and cycle behavior remain open. The bridge is not yet a production-equivalent backend.
- Scheduler extraction progress (boundary parity fix `5b5b150`): `main.c` routes `handle_pending` through `mm_execution_state_dispatch_pending()` before charging/fetching the next instruction. `mm_web_step_instructions()` now follows that ordering: it dispatches already-pending exceptions before the instruction, advances cycles, applies timestamped GPIO input, executes the instruction, and polls target devices at the 64-cycle quantum afterward. An active H563 EXTI fixture queues PA6 for the next cycle, verifies the boundary instruction increments r4 before IRQ entry, then reaches BKPT in the handler; the regression fails against the previous web ordering, which dispatched the new IRQ before that instruction. `wasm_worker_active_exti_boundary_test`, `wasm_worker_wfi_exti_test`, and `web_session_test` pass. Sleeping cores advance to the next SysTick, signal or queued GPIO deadline, capped at the polling quantum; the worker does not reschedule while the core remains asleep. Architectural entry/stacking and EXC_RETURN unstacking live in `execution_exception.c` behind explicit fault, trace, dump, calltrace and NVIC hooks; CLI adapters preserve fault routing and diagnostics, while web callbacks use typed web fault policy. H563 PendSV end-to-end firmware writes ICSR.PENDSVSET, returns through `BX LR`, and reaches BKPT through the public API, natively and under Node/WASM. WFI fixtures verify no following instruction is fetched while asleep and that timestamped input wakes it through EXTI. Existing CLI cross-domain, PSP and IT-state frame regressions pass. Tail chaining remains disabled as in the pre-extraction CLI path. Exact target peripheral callback timing beyond this active GPIO boundary, fault recovery and worker resume behavior still need review.

- Architectural exception operations in `execution_exception.c` include CPACR/NSACR privilege checks for FPU access, FPCA/ASPEN/LSPEN automatic and lazy preservation decisions, Secure-to-Non-secure additional-state selection, Secure callee-register save/clear, banked CFSR/BFAR recording on BusFaults, exception entry/stacking and EXC_RETURN unstacking. Entry/unstack use explicit fault and diagnostics callbacks so CLI policy remains at its adapter; the web bridge supplies its own fault handling. Native and Node/WASM state tests cover basic SVC and H563 PendSV round trips. Web stepping now performs pending IRQ delivery. Full production scheduler parity is not complete.
- Startup also composes target MMIO, memory regions, flash/RAM aliases, code cache, SoC reset, timer, USART/SPI, protection, boot resolution, and peripheral reset. `mm_execution_state_reset_core_system()` and `mm_execution_state_init_core_system()` own the production DWT reset/cycle binding, per-core SCS initialization and MMIO routing, FPU access defaults, and CoreSight registration; `main.c` delegates at the original reset and registration points. Target MMIO registration and flash/SPI memory-map binding also delegate to the state at their original points, preserving GPIO validation order. Tests cover H563 GPIO capability visibility and flash binding, H563 FPU/SCS setup, and the dual-core i.MX RT SCS mux, natively and in the Node/WASM session executable. Protection policy and board-specific startup remain in the CLI. A thin wrapper around `mm_execute_decoded()` alone would omit these production behaviors.
- Signal facilities and static target drivers still contain process-wide state. `mm_execution_state_init()` enforces one initialized session at a time, resets signal stimuli/trigger/time state, and restores the 64 MHz default; destroy clears it again. Signal event countdown and simulated nanoseconds are queried through the active session. Production signal replay setup and access now go through active-session operations: VDD/VIL/VIH configuration, `.sigc` load and GPIO trace binding, trigger configuration/query, CPU-rate changes, per-run preparation, event countdown/time reads, trigger checks, and cycle advancement. Native tests reject state-changing operations on a non-active session and cover threshold and trigger behavior. This makes the current single-worker constraint explicit, but does not provide independent concurrent sessions. Migrating signal stimuli and target peripheral instances into fully session-owned contexts remains required before that boundary can change.
- Board caveat: the supplied H563 layout declares `geometryStatus: stylized_provisional_not_manufacturing_scale` and `electricalMapStatus: UNVERIFIED_VENDOR_SCHEMATIC_REQUIRED`. The official MB1404 H563ZI C-01 schematic pack v2.0 (sheet 6, Connectors) and UM3115 Rev 2 manual (Figure 17 and connector pinout tables) have been reviewed for connector identities and mapping. The supplied H563 layout identifies long headers as CN11/CN12 and side rows as ZIO_D/ZIO_A; it contains no CN7/CN9 connector IDs. Its README explicitly describes connector identities and non-Pico placement as provisional. Therefore PA5/CN7-10 and PA6/CN9-1 remain metadata-only until revision-correct artwork anchors can be matched. Source and review details are in `web/boards/nucleo-h563zi-pins.json`.

## Extraction requirements

1. Complete the typed session API used by CLI and web builds by moving whole-instruction orchestration, scheduler ordering, signal/peripheral time advancement, sleeping-core scheduling and peripheral polling behind session operations. Keep instruction semantics shared; do not fork an approximate browser-only loop. Target/storage ownership, bounded ELF loading, map/cache composition, clock, cycle advancement, fetch/decode, IT handling, decoded execution, sleep wake decision, interrupt selection/dispatch, exception entry/unstack, EXC_RETURN encoding and SCS active-state updates are already shared.
2. Move image loading behind a memory-buffer API. The browser contract starts with bounded ELF32 little-endian ARM PT_LOAD records; validate header/program-table bounds, address ranges and all integer additions before copying.
3. Give session creation the selected target and owned storage, initialize the same target/MMIO/memory/cache peripherals as CLI startup, and return explicit unsupported-feature errors for native-only host backends.
4. Add native tests that load a real H563 ELF from bytes and compare boot PC/register/memory and bounded stepping against the CLI path. Add an Emscripten worker smoke test only after native behavior matches.

## Known implementation risk

The current full loop has intertwined options and globals (GDB/TUI/recording/fault injection/multicore). Split optional CLI policy from shared execution in narrow pieces and keep the native suite green after each extraction. Do not route production browser runs through `step_core_simple()` or `mm_step()` as a shortcut.
