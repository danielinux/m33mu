# WASM execution extraction notes

**Status:** in progress; `mm_execution_state` now owns target/storage, memory/cache, per-core CPU/SCS/NVIC/IT, clock and core-system state, and exposes setup, bounded ELF loading, fetch/decode/fault, decoded execution, WFI/WFE wake and pending-IRQ dispatch operations. The production loop uses these operations, but full scheduler ordering, exception entry/unstack, signal/peripheral instances and a linked worker-facing session API remain incomplete. Reviewed through local HEAD `aed4739`.

## Current paths

- `cmake/wasm` now builds a static core library with `scripts/build-web-core.sh`, excluding `main.c`, GDB sockets, POSIX UART/PTY HAL, Linux Ethernet/USB host modules, optional TPM/capstone sources and TUI. Host-independent target callback dispatch is in `src/target_runtime.c` and is compiled into the WASM core. CTest runs this compile smoke when `emcmake` is found. Static archive creation does not yet prove a linked/runnable session because a WASM-facing entry point and worker protocol are still absent.
- `target_runtime_test` checks dispatch of the extracted target callbacks; its single static current-target pointer also makes the one-live-session constraint explicit. Separately, `mm_execution_state` is now the production session owner used by `main.c`; it is still incomplete because peripheral instances, signal state, exception entry/unstack and whole scheduler control remain outside it.
- `mm_execution_advance_cycles()` now centralizes the production virtual cycle counters, SysTick, target timer and signal clock updates. The CLI's main instruction path, translation-block execution, flash stalls and sleep paths, plus the secondary stepping helper, call this shared routine. Signal-trigger checks stay at the same instruction boundaries. `execution_clock_test` covers counter deltas, zero-cycle behavior, optional counter pointers and target timer advancement.
- The production scheduler counters now have an explicit `mm_execution_clock` owner: total cycles, virtual cycles, realtime sync baseline and poll batch count. The CLI resets this state at each run/reset boundary and both the production loop and secondary-core step helper advance it through `mm_execution_clock_advance()`. The older pointer-based primitive remains for independent callers/tests. CPU, map and code cache are session-owned too; peripheral instances, signal state and broader scheduling policy remain outside the owner.
- `mm_cpu_reset()` in the shared CPU core now clears the complete architectural CPU object and establishes secure thread mode, VTOR banks, and requested sleep state. The production startup/reset path uses the same function for the primary core and parked secondary core, then applies target boot register seeds and reads the reset vector. This makes the reset semantics directly reusable by session creation and prevents stale or uninitialized FP/DSP, stack-tracking, exception-stack, TrustZone-stack and exclusive-monitor state. Native tests check base and parked-core reset; the generated H563 CLI ELF boot remains green.
- `mm_execution_state` owns both cores' CPU, SCS, NVIC and IT-block state, the SCS multiplexer, active-core selector, scheduler clock, production map/MMIO storage/code cache, protection contexts, core-system context, selected target, flash/RAM storage and loader targets. `main.c` uses these members directly. State operations cover lifecycle, staged target setup, ELF loading, reset-vector application plus VTOR synchronization, fetch/decode, fetch-fault callback dispatch, IT decisions/advancement and skip/execute, decoded execution, sleep wake and pending interrupt dispatch. Native tests cover these owned operations. The actual peripheral instances, signal facilities, full instruction scheduling and exception entry/unstack remain outside the owner.
- `execution_irq.c` owns exception-priority and mask decisions. `mm_execution_irq_dispatch_pending()` applies PendSV/SysTick/IRQ candidate selection and delivery bookkeeping. `mm_execution_state_dispatch_pending()` binds that dispatch to owned per-core state and is used by the primary scheduler; its `SKIP_BLOCKED` policy preserves production fallthrough. `step_core_simple()` retains `STOP_ON_BLOCKED`. Exception entry remains injected from `main.c`; a browser session needs an equivalent shared exception-entry implementation before it can use asynchronous dispatch independently. Tests cover both policies, bank selection, priority lookup, BASEPRI and external IRQ bookkeeping.
- `exc_return.c` now owns Armv8-M EXC_RETURN encoding and decoding. The extended encoder preserves distinct stack and exception security state, PSP/thread mode, frame type and default callee stacking; the legacy three-argument API is a compatibility wrapper. Production exception and fault paths use the extended encoder. `scs.c` now owns banked SHCSR exception-active set/clear and ICSR VECTACTIVE updates, used by production exception delivery and return. Tests cover encoder/decoder field round trips and banked SCS updates. Full exception entry, stacking/unstacking, tail chaining and fault diagnostics remain in `main.c`.
- `mm_target_storage` in `target_storage.c` owns target flash and RAM backing allocations. It computes RAM storage from non-aliased RAM regions, provides a safe destroy operation, and leaves the object empty on failed initialization. It is embedded in `mm_execution_state` and used by CLI/session setup; peripheral instances, signal state and parts of reset policy are still in `main.c` or process-global modules.
- `mm_elf_load_memory_bounded()` accepts a byte buffer and caller-selected maximum size, rejects oversized inputs before segment writes, validates ELF32 little-endian ARM program-header and segment bounds, maps PT_LOAD data into caller-owned flash/RAM/serial-flash buffers, and reports loaded address range. The compatibility `mm_elf_load_memory()` retains the prior no-policy-limit behavior and CLI path loading delegates to it. `image_loader_test` covers the cap rejection and accepted boundary; `scripts/test-web-elf-loader.sh` links the loader test as WASM and runs it in Node; CTest registers this smoke when `emcc` and Node are found. The browser/session caller still needs to set the product-specific maximum.
- `scripts/test_cli_elf_loader.py` generates a minimal H563 ELF with a reset vector and BKPT, then verifies normal CLI loading, reset, and instruction execution. This confirms the path wrapper and in-memory parser work together.
- Remaining loader gaps: selecting and enforcing the browser product input limit, validating a real H563 ELF against CLI boot state through the session API, and browser worker integration. The parser test covers a flash PT_LOAD, linked-at-zero flash offset, rejection of an oversized buffer and rejection of a malformed later segment without partial writes.
- `src/main.c::step_core_simple()` handles a limited subset of timing/exception logic for a secondary path. `src/runloop.c::mm_step()` executes only NOP and branch placeholders. Neither is the production H563 path.
- The primary production path uses session operations for reset-vector application, fetch/decode, fetch-fault callback dispatch, IT decisions/advancement, IT predicate skip versus execute, and decoded execution. `mm_execution_state_run_decoded()` is used by `main.c` and preserves the rule that an IT instruction executes regardless of the current predicate. The CLI supplies policy callbacks and output state. The session also applies WFI/WFE wake rules and dispatches pending exceptions using owned CPU/map/SCS/NVIC/IT state. Cycle timing, trace/CLI policy, asynchronous exception entry/unstack, peripheral polling, and full scheduler ordering remain in `main.c` or process-wide modules.
- Startup also composes target MMIO, memory regions, flash/RAM aliases, code cache, SoC reset, timer, USART/SPI, protection, boot resolution, and peripheral reset. A thin wrapper around `mm_execute_decoded()` alone would omit these production behaviors.
- Process-wide state in memory-map and signal facilities, and static target drivers, means the planned first API must own and enforce one live session. Concurrent session isolation is not an incidental worker feature.
- Board caveat: the supplied H563 layout declares `geometryStatus: stylized_provisional_not_manufacturing_scale` and `electricalMapStatus: UNVERIFIED_VENDOR_SCHEMATIC_REQUIRED`. ST's official CMSIS-Pack documentation identifies the MB1404 C01 schematic, but the drawing has not been reviewed. The supplied H563 layout identifies long headers as CN11/CN12 and side rows as ZIO_D/ZIO_A; it contains no CN7/CN9 connector IDs. Its README explicitly describes connector identities and non-Pico placement as provisional. Therefore PA5/CN7-10 and PA6/CN9-1 remain metadata-only until the schematic and revision-correct artwork establish matching physical contacts.

## Extraction requirements

1. Complete the typed session API used by CLI and web builds by moving whole-instruction orchestration, scheduler ordering, signal/peripheral time advancement and exception entry/unstack behind session operations. Keep instruction semantics shared; do not fork an approximate browser-only loop. Target/storage ownership, bounded ELF loading, map/cache composition, clock, cycle advancement, fetch/decode, IT handling, decoded execution, sleep wake, interrupt selection/dispatch, EXC_RETURN encoding and SCS active-state updates are already shared.
2. Move image loading behind a memory-buffer API. The browser contract starts with bounded ELF32 little-endian ARM PT_LOAD records; validate header/program-table bounds, address ranges and all integer additions before copying.
3. Give session creation the selected target and owned storage, initialize the same target/MMIO/memory/cache peripherals as CLI startup, and return explicit unsupported-feature errors for native-only host backends.
4. Add native tests that load a real H563 ELF from bytes and compare boot PC/register/memory and bounded stepping against the CLI path. Add an Emscripten worker smoke test only after native behavior matches.

## Known implementation risk

The current full loop has intertwined options and globals (GDB/TUI/recording/fault injection/multicore). Split optional CLI policy from shared execution in narrow pieces and keep the native suite green after each extraction. Do not route production browser runs through `step_core_simple()` or `mm_step()` as a shortcut.
