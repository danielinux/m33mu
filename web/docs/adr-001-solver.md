# ADR-001: primary circuit solver

**Status:** Decided 2026-10-24: the workbench ships its own MNA solver (`web/sim/`, AGPL-3.0-or-later, no third-party code or models). Perun and ngspice remain external reference oracles only. The original evaluation record below is kept as history.
**Date:** 2026-10-23 (opened), 2026-10-24 (decided)

## Context

The workbench requires deterministic transient stepping with source changes during a run, state preservation, worker yielding, pause/resume, and event localization at MCU input thresholds. A completed batch `.tran` result is insufficient because firmware GPIO writes and circuit voltages must share virtual time.

## Evidence so far

- A reproducible **live shared-clock proof of concept** now runs H563 firmware in the public Emscripten API and advances Perun's 1 kOhm/10 nF RC transient on the same 64 MHz cycle count, at one solver step per CPU cycle (15.625 ns). Firmware PA5 drives 3.3 V/0 V; 1775/1525 mV crossings schedule timestamped PA6 events into H563 EXTI, whose handler toggles PA5. The pinned Perun engine detects four crossings at cycles 557, 678, 799 and 920; the corresponding feedback output transitions occur at 569, 690, 811 and 932 after interrupt entry/handler latency. Public output timestamps are queued and the drive changes only at the matching solver boundary; the harness fails if an output is discovered after that boundary or if a crossing cannot be queued before firmware advances past it. Linear interpolation between solver samples locates the four crossings; comparison with the analytic 1 kOhm/10 nF RC response from the measured voltage at each drive edge has maximum absolute error **0.915 CPU cycles (14.3 ns)**. The test enforces an error below one cycle for this fixture. Both clocks finish at cycle 940 and firmware reaches its success BKPT. `scripts/run-web-live-coupling-probe.sh /path/to/pinned/Perun` builds a temporary WASM module, runs the external harness, and regenerates `web/fixtures/solver/perun-live-coupling.json`; test source: `scripts/live-m33mu-coupling-probe.test.ts`. No Perun source is copied into the repository or bundle. This does not establish tolerances for other circuits/models, a general rollback mechanism, a shared worker budget/yield loop, or representative device breadth. Perun remains unselected pending those checks and distribution license work.

- The public `eecircuit-engine` TypeScript API (`eelab-dev/EEcircuit-engine` at `75594eec516be3087e64eeb5347a958de70f410c`, MIT) exposes `setNetList()` and `runSim()`. Its implementation runs `source test.cir`, `destroy all`, `run`, and then reads `out.raw`. There is no public incremental step/source-update API. **Reject this wrapper as-is** for the live workbench; the underlying WASM core could be reconsidered only after an incremental control API and its license/model provenance are demonstrated.
- CircuitJS1 at `778723096a46f3c5ce4e11bd9edc24324754f02c` is GPL-2.0-or-later. `SimulationManager.runCircuit()` performs `startIteration()`, element `doStep()`, matrix solve, `stepFinished()`, and `app.onTimeStep()`, but it loops according to `Date.now()`, speed controls, frame limits, and `app.simRunning`. It calls back into `CirSim`, and `CirSim.onTimeStep()` updates scopes and hooks. `CircuitMatrix` is a plausible numerical component, but no single-quantum headless API or mid-transient source-update test has been produced. It needs a bounded-step extraction before it can be evaluated for the worker; it is not selected.
- A newer public TypeScript port, `noiseweaver/Perun` at `067d1c9c59e27f72f6498ec224f3735d0da6364a`, separates a no-DOM `Simulation` engine. Its `packages/engine/src/Simulation.ts` header identifies GPL-2.0-or-later and says it ports CircuitJS1's TypeScript engine at `7ec858d662d8be1d76d54241ba3a5c1d1c524f51`, checked against upstream Java `SimulationManager` at `5a707168778216bb6ed01bfdd62e8bbf7ae0a032`. `Simulation.step(n)` synchronously runs a requested count of transient steps and returns the count completed; `setElements()` retains the element objects while flagging re-analysis. In an isolated `/tmp` checkout at the pinned Perun commit, `pnpm --filter @perun/engine typecheck` passed and `pnpm exec vitest run tools/golden/src/next.test.ts` passed 132 fixture tests. A temporary RC probe changed a DC source from 5 V to 0 V mid-run, forced re-analysis, confirmed capacitor voltage remained continuous across the first 5 us step and then discharged, confirmed pause stopped after one step and resume advanced again, and localized the 1 V RC crossing to within one 5 us solver quantum. The probe files and dependency checkout are outside this repository; no solver code was imported. This establishes a credible deterministic incremental candidate, but not firmware GPIO/EXTI coupling, nonlinear device parity for this workbench, worker yielding under a budget, or complete license compatibility. Keep selection open pending those checks.

## Decision (2026-10-24)

Select the in-repository solver in `web/sim/circuit.ts` as the single production solver. Reasons:

1. **Rollback is required by the coupling design.** The worker scheduler (`web/sim/bench.ts`) solves the circuit ahead of the firmware, queues predicted input crossings, and must retract the circuit to the exact instant firmware changes a pad. That needs a cheap, exact snapshot/restore of every dynamic quantity. Perun keeps state inside CircuitJS element objects and ngspice inside its C circuit structures; neither exposes a restorable state, and the only alternative found (lockstep at one solver step per CPU cycle, as in the live Perun probe) costs 64 million solver steps per simulated second at 64 MHz.
2. **Event localization at the threshold.** The solver localizes Schmitt-threshold crossings by Illinois regula falsi on the step size to 0.25 ns, instead of interpolating between fixed steps.
3. **Distribution.** No GPL/Apache/LGPL notice closure is needed for shipped code; the bundle contains only project code plus React (MIT). Perun's GPLv3 + Apache-2.0 packaging and ngspice's LGPL/BSD closure (both documented above) are avoided rather than packaged.

Scope of the shipped solver: R, C, L, independent V/I sources, SPST switch, Shockley diode with optional reverse breakdown, LED (diode model plus rated current), Ebers-Moll transport NPN/PNP (IS, BF, BR; no Early effect, no junction capacitance), Level-1 Shichman-Hodges NMOS/PMOS (VTO, KP, LAMBDA; no body effect, no capacitances), and the MCU pad model in `web/docs/electrical-model.md`. Dense LU with partial pivoting, Newton with SPICE `pnjlim`/`fetlim`/`limvds` limiting, gmin and source stepping for the DC operating point, backward Euler after every discontinuity then trapezoidal integration with divided-difference LTE control (RELTOL 1e-4, TRTOL 1, 10 uV absolute). Unsupported devices are rejected by `validateNetlist` with an explicit message.

P2 extension: `opamp` is a five-terminal macro model with differential input resistance, finite output resistance, open-loop gain and a smooth output limit inside the supply rails. Output current is sourced from VCC or returned to VEE with a continuous current split around zero. The checked-in gain-two example and solver fixtures cover closed-loop DC gain, loaded rail saturation, supply current, capacitive-load transient and exact snapshot/restore. This model has no bandwidth, slew rate, input offset, common-mode range, current limit or temperature behavior; it is not a vendor IC model.

Limits: no adaptive model temperature, no junction or gate capacitance, no regulator or transformer models yet, dense LU (intended for breadboard-sized circuits up to a few hundred unknowns). These remain P2 items.

## Previous decision (2026-10-23, superseded)

Defer selection. Do not wire firmware GPIO into an assumed ideal voltage source. Perun now passes pinned reference fixtures, bounded stepping, RC source-update/state-continuity, pause/resume and one-quantum threshold localization probes. Both staged and live H563/Perun RC-to-EXTI proofs reach firmware success. The live proof measures causal ordering at a one-CPU-cycle solver quantum; the staged probe still reports up to 6.658 us analytic timing error for a 5 us solver quantum and boundary-quantized source updates. The matched diode and NPN operating points add narrow DC evidence, but they remain narrow fixtures; shared worker budget/yield loop, general rollback mechanism, or product-wide accuracy threshold. Preliminary source-level review suggests the engine's declared runtime dependency set is empty and a GPLv3 choice may combine with this AGPLv3 project, but sparse-matrix Apache notices and complete final-distribution provenance remain to be checked. ngspice 47+ds-1 can be compiled as a WASM shared object after a temporary source workaround; dynamic-linking stability and file-level license closure remain unresolved. Select only after shared scheduling, broader fixtures, documented tolerance, causal ordering, and license provenance pass.

## Required evidence to close

1. Mid-transient source changes without resetting unrelated reactive state.
2. A controllable simulation quantum, bounded worker execution, pause/resume, and deterministic replay.
3. Firmware output edge -> analog RC threshold crossing -> GPIO/EXTI event with ordering and timing tolerance measured against a reference fixture.
4. Numerical fixture comparisons, solver build ID, license notices and complete model/dependency provenance.
