## Not supported (shown as such in the UI)

- ADC, DAC, TIM1/TIM8 and every alternate function other than TIM2-TIM5 channels and the I²C/SPI/UART buses: such an AF-mode pad is high impedance and the bench raises an `unsupported` notice. On-board LEDs and the user button do not load their pads electrically.
- I²C, SPI and UART are logic level (transactions, not bit edges): wiring and solved line levels decide routing and faults (see `buses.md`). Bus pads stay high impedance in the analog circuit; device outputs are not analog drivers.
- The other 14 boards (display assets exist, no reviewed mapping, no browser firmware profile).
- More than one MCU per bench; more than one emulator session per worker (process-global target state).
- Op-amp frequency response, slew rate, common-mode range and input offset; regulator line/load transients, thermal and current limits, transformers, junction/gate capacitance, temperature. The available op-amp is a rail-limited macro model, not a device-specific IC.
- Scope trigger uses sampled values with linear crossing interpolation. Auto follows the latest complete edge or free runs; Normal waits for an edge and displays each complete capture; Single freezes the first complete capture until rearmed. The modes are saved in project v2. Acquisition and manual hold affect the scope display and exports; they do not stop the emulator or provide pre-sample event localization. A requested window larger than retained samples cannot be captured and is warned about in the UI.
- SIGC import previews up to two voltage traces; it does not drive MCU inputs or persist in project JSON. See `scope-capture.md`.
- Timing: one virtual cycle per instruction (no pipeline/bus model); the CLI's default translated-block mode takes interrupts at block boundaries and differs from the instruction-stepped web scheduler (14 cycles on the parity fixture).
- Browsers: only Chromium is tested (Firefox and WebKit drivers were not available in the build environment).
